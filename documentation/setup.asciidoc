== Setup

This chapter prepares your workstation for all exercises.
You install the tools, build the project, start the database and the identity server (Keycloak) as Docker containers and learn how to start, debug and test the application from your IDE.

=== How the training environment works

During the exercises the application is split as follows:

[options="header",cols="2,3,3"]
|===
| Part | Runs as | Reachable at
| PostgreSQL (database) | Docker container (`docker-compose.db.yaml`) | `localhost:5432`, database `quarkus`, user and password `quarkus`
| Keycloak (login, users and roles) | Docker container (`docker-compose.auth.yaml`) | http://localhost:8180/ (admin console: `admin` / `admin`)
| Backend (Quarkus) | started by you from the IDE in *dev mode* | http://localhost:8080/ (REST API below `/api`)
| Frontend (React) | delivered by the backend (Quinoa), you do not start it separately | http://localhost:8080/
| Ollama (AI model, used in the inter-service exercise) | Docker container (`docker-compose.ollama.yaml`) | `localhost:11434`
|===

So the only thing you have to start yourself besides the containers is the backend.
Open the web application always via http://localhost:8080/ and log in with one of the test users (the password is the same as the username):

[options="header"]
|===
| User | Intended for
| `reader` | only reading
| `writer` | reading and writing
| `manager` | reading, writing and deleting
|===

NOTE: *Dev mode* is the way Quarkus is started during development: it reloads your changes automatically, offers a debugger port and a developer UI.
Quarkus can also start a database and a Keycloak on its own in dev mode (*Dev Services*).
We do not use that for running the application, as the containers above are started once and keep their data.
Dev Services are only used by the automated tests (see <<_run_the_tests,Run the tests>>).
In the docker exercise you will additionally learn how the application runs without dev mode in a container.

=== Install the tools

Install https://github.com/devonfw/IDEasy[IDEasy]:

* Install https://git-scm.com/downloads[git] if not already installed (download and run installer or run `winget install Git.Git` in PowerShell or CMD)
* Install https://github.com/devonfw/IDEasy/releases[IDEasy] (see https://github.com/devonfw/IDEasy/issues/1102[#1102] for Windows and https://github.com/devonfw/IDEasy/issues/451[#451] for Mac)
* Run the following command in your terminal (git-bash):
+
```
ide create java-quarkus https://github.com/devonfw-training/java-quarkus-settings.git#main
```
* Wait until the setup process has completed.
This installs the tools you need for the exercises (among others Java and Maven) and the IDEs.
* If you do not have already Docker Desktop or Rancher Desktop installed, you should do so by running in Git-Bash the command:
+
```
icd -p java-quarkus
ide install docker
```

=== Build the backend

Now we build our application:

* Run the following commands in your terminal (git-bash):
+
```
icd -p java-quarkus -w main
cd java-quarkus
mvn clean install -DskipTests
```
+
All following commands in this chapter are executed in this folder (the top-level folder of the project that contains the `docker-compose*.yaml` files), if not stated otherwise.
The build also builds the frontend (with `npm`) and embeds it into the backend, so it needs an internet connection and takes a few minutes the first time.

=== Start Docker and the containers

The database and Keycloak run in Docker containers.
The following steps have to be repeated after every reboot of your computer (or whenever you stopped Docker).

. Start *Docker Desktop* or *Rancher Desktop* and wait until it reports that it is running.
. Check in your terminal that Docker is reachable:
+
[source,bash]
----
docker ps
----
+
This lists the running containers (the list may be empty).
If you get an error like _Cannot connect to the Docker daemon_, Docker is not (yet) running.
. Start the database and Keycloak:
+
[source,bash]
----
docker compose -f docker-compose.db.yaml -f docker-compose.auth.yaml up -d
----
+
The option `-d` starts the containers in the background.
The first time Docker downloads the images, which can take a few minutes.
. Check that both containers are running:
+
[source,bash]
----
docker compose -f docker-compose.db.yaml -f docker-compose.auth.yaml ps
----
+
The status of `postgres` should become `healthy`, the one of `keycloak` should be `Up`.
Keycloak needs a short while to start (typically well under a minute); you can follow it with `docker compose -f docker-compose.auth.yaml logs -f keycloak` (leave with `[Ctrl][c]`).
You can also open http://localhost:8180/ in your browser.

The application is split into several compose files, so you start only what you need:

[options="header",cols="3,3,4"]
|===
| File | Contains | Needed for
| `docker-compose.db.yaml` | PostgreSQL | running the application (always)
| `docker-compose.auth.yaml` | Keycloak | running the application (always)
| `docker-compose.ollama.yaml` | Ollama (AI model) | the exercise link:inter-service-communication.adoc[inter-service communication]
| `docker-compose.app.yaml` | backend and frontend as containers | the exercise link:docker-compose.asciidoc[docker-compose], not for development in the IDE
| `docker-compose.yaml` | includes all files above | `docker compose up --build` starts everything at once
|===

Useful commands (use the same `-f` options as above, or fewer if you only want to address one file):

[options="header",cols="2,3"]
|===
| Command | Effect
| `docker compose -f docker-compose.db.yaml -f docker-compose.auth.yaml stop` | stops the containers, they and their data are kept
| `docker compose -f docker-compose.db.yaml -f docker-compose.auth.yaml start` | starts stopped containers again
| `docker compose -f docker-compose.db.yaml -f docker-compose.auth.yaml down` | stops and removes the containers, the database content is kept in a volume
| `docker compose -f docker-compose.db.yaml -f docker-compose.auth.yaml down -v` | additionally deletes the volume, i.e. the database content (a fresh start, also needed after you changed an already applied Flyway script)
| `docker compose -f docker-compose.db.yaml logs postgres` | shows the log of a service
|===

NOTE: Keycloak keeps its data (users, roles) only as long as its container exists.
Whenever the container is created, it imports the realm from `backend/src/main/resources/keycloak/quarkus-realm.json`.
If you change this file, recreate the container: `docker compose -f docker-compose.auth.yaml up -d --force-recreate keycloak`.

=== Import into an IDE

Please choose your favorite IDE.
For best support from the trainers we recommend to use IntelliJ.

==== IntelliJ

* Launch IntelliJ via `ide intellij`
* In your IntelliJ `Project` view open the `java-quarkus` folder and select `pom.xml`.
* Right-click on it and select `+ Add as maven project`
* Wait until IntelliJ has imported the project and indexed it (see the progress bar at the bottom right).
The module `app` appears in the `Project` view.
* Check that a Java 21 SDK is used: `File` > `Project Structure` > `Project`.

===== Start the application in dev mode

Before you start the application, the containers of the previous section must be running.

With IntelliJ IDEA Ultimate and its Quarkus plugin:

* At the top right of the IntelliJ window select the run configuration `Quarkus Dev Mode` for module `app` (name `app`).
If it does not exist, create it: `Run` > `Edit Configurations...` > `+` > `Quarkus Dev Mode` and select the module `app`.
* Click the green *Run* button, or the *Debug* button (bug icon) if you want to set breakpoints.
* In the `Run` tool window you see the startup output.
After a few seconds you should see the lines
+
----
... app 1.0.0-SNAPSHOT on JVM (powered by Quarkus ...) started in ...s. Listening on: http://localhost:8080
... Profile dev activated. Live Coding activated.
----

Alternatively (also works with IntelliJ Community Edition and on the command line):

* Open the `Maven` tool window, expand `app` > `Plugins` > `quarkus` and double-click `quarkus:dev`.
* On the command line run `mvn quarkus:dev` in the folder `backend`.
* To debug, create a `Remote JVM Debug` run configuration (`Run` > `Edit Configurations...` > `+` > `Remote JVM Debug`) with host `localhost` and port `5005`, and start it with the *Debug* button while the application is running.
Dev mode listens on this port for a debugger.

Then:

* Open http://localhost:8080/ in your browser.
You are redirected to the login page of Keycloak.
Log in with `writer` / `writer`; you should see the list of todo lists.
* The REST API is served below `/api` (the web application calls e.g. `/api/task/lists`).
* http://localhost:8080/q/swagger-ui shows the documentation of the REST API and lets you try it.
* http://localhost:8080/q/dev-ui shows the developer UI of Quarkus.

Things to know in dev mode:

* *Live reload*: when you change Java code, configuration or resources while the application is running, simply reload the page or call the REST API again.
Quarkus rebuilds and restarts the application automatically on the next request.
You do not need to stop and start it.
When the code does not compile, the error is shown in the browser and the console.
* *Frontend*: Quarkus starts the development server of the frontend (Vite) for you and forwards requests to it, so changes in `frontend/src` are shown immediately, too.
You do not run `npm start` yourself.
* *Stop* the application with the red *Stop* button of the `Run` tool window.
Make sure that no other instance is still running, otherwise the port `8080` is occupied.

==== Eclipse

Next, we import the `backend` project into our Eclipse IDE:

* `ide eclipse`
* In Eclipse `Import` as `Existing Maven Project`, there click `Browse` and choose your `backend` folder in `workspaces/main/java-quarkus`.
* Now find the green bug icon in the Eclipse toolbar and click on the down-arrow right to it.
* Click `Debug Configuration` from the menu
* In the appearing `Debug Configuration` popup window select `Quarkus application` from the list on the left.
* Click on the first icon from the bar above that list (with tooltip `New launch configuration`)
* Change the `Name` to `app` and ensure the `Project` is set to `app`.
* Click on `Debug` to start your app in debug mode.
* Open http://localhost:8080/ in your browser, as described above for IntelliJ.

=== Run the tests

You can run tests in the IDE and with Maven.
Tests do not need the application to be running, and they do not use the data of your containers.
Instead, Quarkus starts a separate PostgreSQL database and a Keycloak for the tests (Dev Services).
Therefore:

* *Docker must be running* (you do not have to start the compose containers for the tests).
* The tests start their Keycloak on port `8180`.
*Stop the Keycloak container* of docker compose before you run the tests, otherwise they fail with _port is already allocated_:
+
[source,bash]
----
docker compose -f docker-compose.auth.yaml stop
----
+
Start it again afterwards with `docker compose -f docker-compose.auth.yaml start` if you want to use the web application.
* The first run takes longer, because Docker has to download the images.

*In IntelliJ:*

* Open a test class and click the green arrow in the margin next to the class or a test method, then select `Run` (or `Debug`).
* To run all tests of a package or of the module, right-click it (e.g. `src/test/java`) in the `Project` view and select `Run 'Tests in ...'`.
* Results are shown in the `Run` tool window; click a failed test to see the reason.

*With Maven* (in the top-level folder):

[source,bash]
----
mvn test                       # unit tests and @QuarkusTest tests
mvn verify                     # additionally packages the application and runs the integration tests (*IT)
mvn test -Dtest=TaskServiceTest  # only one test class
----

NOTE: Tests whose class name ends with `IT` (e.g. `TaskServiceIT`) are integration tests that run against the packaged application.
They are only executed by `mvn verify`, not by `mvn test`.

=== Typical problems

[options="header",cols="3,4"]
|===
| Problem | Solution
| `Cannot connect to the Docker daemon` or tests fail right at the start | Docker Desktop / Rancher Desktop is not running. Start it and wait until it is ready.
| `Port 8080 already in use` when starting the application | Another instance of the application is still running. Stop it (also check the `Run` tool window of IntelliJ and your terminals).
| `port is already allocated` for `8180` or `5432` when starting containers or tests | Something else uses this port. For tests: stop the Keycloak container (see above). Otherwise stop the program or container that uses it, e.g. check with `docker ps`.
| Application fails with a connection error to the database (`localhost:5432`) | The container `postgres` is not running (`docker compose -f docker-compose.db.yaml ps`).
| Login page does not open or the application hangs while starting | Keycloak is not running or still starting. Wait until `docker compose -f docker-compose.auth.yaml logs keycloak` shows that it started, then reload.
| After login the web application shows `No permissions` | You are logged in as a user without the required role, e.g. `reader` tries to delete. Log in as `manager`. If every user is denied, the realm was changed: recreate the Keycloak container (see above).
| Tests fail or run that you do not know, e.g. after you switched the git branch | Old compiled classes remain in the folder `backend/target`. Run `mvn clean` once (or `mvn clean test`).
| `Flyway` reports a checksum or migration error after you changed an SQL script | The database still contains the old version. Reset it with `docker compose -f docker-compose.db.yaml down -v` and start it again.
|===
